# v0.1.0 — evidence baseline

*Draft. Not tagged or published; see the
[public-release checklist](public-release-checklist.md).*

The first public slice of the Jev Enterprise Decision Fabric: a way to run many
semantic decisions through one validated path, a labelled benchmark that
measures whether the resulting decisions are right, and a dashboard for reading
any single decision back out of the evidence.

Everything here runs from a clean clone with no provider key and no network
access.

## What is in it

**The fabric.** `IDecisionPack<TInput, TOutcome>` and `IDecisionFabric`: a
decision point is a versioned contract, a mapping from domain input to model
state, and a deterministic policy. One batched request per state, every answer
validated before a policy sees it, and a `PolicyFingerprint` so a threshold
change is visible in the output.

**Two gates.** A destructive-action gate behind a payment dispute API, and a
proposed-action gate that decides whether an agent's tool call may run
unattended, needs approval, or is denied.

**An evaluation runner.** JSON-driven, with disposition accuracy on both
denominators, unsafe-allow and over-block counts reported apart from accuracy,
stability across repeats, latency percentiles, token usage and cost. `compare`
diffs two reports; `rebuild-report` re-derives every decision from recorded
answers and refuses to proceed if one no longer reproduces.

**A labelled dataset.** `agent-action-gate-v1`: 111 proposed tool calls across
15 failure-mode families, with the annotation rules and the one label revision
recorded inside the dataset itself.

**A recorded comparison** of TypeSafe Jev against a structured-output Claude
Opus 5 baseline, with raw JSONL committed for both legs.

**The Decision Inspector.** A read-only dashboard over the recorded runs,
showing one case at a time in three layers.

## What the benchmark found

Both legs, 2026-09-19, `--max-repetitions 5`, 243 calls each:

| | Jev | Claude Opus 5 (low) |
| --- | ---: | ---: |
| Per-case accuracy | 100/111 (90.1%) | 102/111 (91.9%) |
| Call-weighted accuracy | 224/243 (92.2%) | 218/243 (89.7%) |
| Unsafe allows / over-blocks | 1 / 1 | 1 / 1 |
| Changed decision across repeats | 0 of 33 | 0 of 33 |
| Latency p50 | 376 ms | 2,479 ms |

The denominators rank the legs differently, which is why both are published.
The legs disagree on 10 cases with one right and one wrong; an exact McNemar
test gives p ≈ 0.75. **This is comparable quality, not a ranking.** Jev was
about 6.5× faster at p50. Claude cost $0.008648 per decision at list price with
no caching; Jev pricing is not publicly available, so no cost comparison is
made.

Two findings are worth more than the headline:

- The one unsafe allow is a **contract gap**, not a model misread. Both
  providers classified an access revocation as `reversible_change`; only a
  confidence floor escalated one of them. The impact vocabulary has no category
  for an action that is reversible in principle and high-consequence in
  practice.
- The largest single error source for both providers is **the gate's own
  mapping** of a low "was this requested" probability to `Deny` where the
  annotation rules want approval. It is deliberately left unchanged rather than
  tuned to improve these numbers.

## Integrity properties

- Committed reports are reproducible from the committed raw answers without
  contacting a provider.
- The inspector republishes report aggregates rather than recomputing them, and
  scores the recorded calls independently only to verify the two still agree. A
  disagreement stops it starting.
- Whether a call matched its label is derived from the disposition and the
  label, never from a record asserting its own correctness.
- CI validates every dataset in `evals/datasets/`, builds with warnings as
  errors, and runs 112 tests.

## Known limitations

One dataset, 111 cases, one annotator; labels revised once after a Jev pilot
before any other provider ran; one baseline configuration; cases written to
probe this policy; stability measured over five repeats in one session; latency
from one machine in one session. Thresholds are hypotheses and several outcomes
sit within ±0.01 of a boundary. The read-only auto-allow rule assumes identity,
authorization and data-access controls are enforced upstream.

This is independent experimental work, not an official TypeSafe AI project, and
not production software.

```bash
  --dataset evals/datasets/agent-action-gate-v1.json --dry-run
dotnet run --project samples/DecisionFabric.Inspector
```

## Frozen for v0.1

Datasets, recorded results, contracts and policies are frozen as the evidence
baseline. Multilingual and adversarial variants, the "not requested at all"
versus "requested but exceeded" policy change, and a category for
consequential-but-reversible actions are all deferred to v0.2, because each
would change a published number.
